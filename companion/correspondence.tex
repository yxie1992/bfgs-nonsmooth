The machine-readable correspondence is part of this report's source release.
It is designed to expose whole theorem contracts and all dependencies, rather
than offer a sample export as a substitute for a proof.

The formal source project remains in \path{bfgs_lean_stage1/}. Its pinned
\path{lean-toolchain}, \path{lakefile.toml} and \path{lake-manifest.json}
are authoritative. On a new supported system, run
\texttt{bash scripts/bootstrap.sh} there, then the fresh audit command in
Chapter~\ref{comp:E}. Network access is needed to obtain the pinned toolchain
and dependencies when they are absent. The release archive omits those large
caches and preserves the source tree's relative paths.

To rebuild the documents from the repository root, run
\texttt{bash editorial/build.sh}. The normal journal class used for the article
is supplied under \path{editorial/vendor/svjour3/} with the original notices
and download provenance. PDF figures are generated from stated mathematical
data; their code is in \path{paper/figures/}. The figure computations are
renderings, not additional formal proof premises. Build logs, page-level
rendering evidence and editorial review findings are kept under
\path{editorial/logs/} and \path{editorial/reviews/}.

Source transformations preserve the corrected mathematical assertions.
Exact Lean contracts can contain definitions that abbreviate substantial
hypotheses; the declaration index exposes their definitions and dependency
closure. Reading one exported name without expanding those contracts would
not validate the prose. Correspondence review is a separate logical bridge
from kernel checking, and author approval remains necessary before submission.
