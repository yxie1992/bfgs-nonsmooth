# Instructions for agents working in this repository

This repository holds a research article on BFGS for nonsmooth optimization
(`paper/`), its companion report (`companion/`) and their Lean 4 formalization.
Author: Yuchen Xie. All reviews so far, including the Lean coverage, were done by
AI agents (Claude in OpenCode); the author's own expert check comes last.

**Start with `HANDOFF.md`:** the current state, setting up a new machine, and how
to resume.

## Plan agreed with the author

1. **Lean coverage of every claim** of the article and the companion. The author:
   "We want lean to have 100% coverage for all proofs and claims on both main
   manuscript and companion. Feel free to author lean codes." Method:
   `editorial/lean_coverage/README.md`; progress: `TODO_LEAN_COVERAGE.md`. The
   article is done; the companion is in progress.
2. **Only after the Lean work is completely done:** a line-by-line reading of the
   article's proofs, and the manuscript corrections listed in
   `TODO_MANUSCRIPT_REVIEW.md` (M7 onwards).
3. The author's own expert check.

## Standing preferences

- Record every issue found as a TODO item (`TODO_LEAN_REVIEW.md`,
  `TODO_MANUSCRIPT_REVIEW.md`, `TODO_LEAN_COVERAGE.md`), then commit and push.
  Agents may edit the repository, commit and push.
- After editing the article or the companion, build the PDF and inspect the
  changed pages visually (render them to images and look at them); also compare
  the LaTeX warnings with those of the previous build.
- Context pruning (DCP): at the agent's own discretion, when the context window is
  getting large, when everything needed is safely stored in files, or when it is
  clear what can be pruned without loss.

## Commands

Lean (elan; `lean-toolchain` selects Lean 4.19.0):

    export PATH="$HOME/.elan/bin:$PATH"
    cd bfgs_lean_article
    lake build                                         # everything (default targets)
    lake build BfgsArticle.Coverage.Article.Energy     # one module
    LEAN_NUM_THREADS=4 lake env lean BfgsArticle/Coverage/Article/Energy.lean   # check one file

Never `lake update`. Never `lake build` or `lake clean` while subagents run Lean in
the package. `lake` has no `-j` option: build modules one after another. Axiom
audit and kernel replay: `bfgs_lean_article/README.md`.

Coverage, ledger, companion:

    python3 editorial/lean_coverage/check_coverage.py [--strict [--allow-discrepancies]] [TEX_FILE ...]
    python3 editorial/lean_coverage/extract_items.py [--json | --init]
    python3 editorial/lean_coverage/companion_hints.py   # git-ignored hints/ for companion agents
    (cd editorial && python3 assemble_claim_ledger.py)   # CLAIM_LEDGER.json, companion/PROOF_CORRESPONDENCE.html
    python3 editorial/generate_companion.py [--check]
    python3 editorial/prepare_shared_appendix.py

PDFs (output `build/master.pdf`, git-ignored; the same in `companion/`):

    cd paper
    export TEXINPUTS="$PWD/../editorial/vendor/svjour3//:" SOURCE_DATE_EPOCH=1789199005 FORCE_SOURCE_DATE=1
    latexmk -g -pdf -interaction=nonstopmode -halt-on-error -file-line-error -outdir=build master.tex

Visual check: keep a copy of the previous PDF, find the changed pages by comparing
the text of each page (PyMuPDF), render them (`page.get_pixmap(dpi=110)`) and look
at the images.

The scripts in `editorial/`, `editorial/lean_coverage/` and
`bfgs_lean_article/scripts/` need Python 3.11 or newer (`kernel_replay.py` uses
`tomllib`) and only its standard library; `editorial/render_review.py` also needs
Pillow and Poppler. Long runs (a clean build of the main library: 10+ minutes;
the axiom audit and the kernel replay: about 5 minutes each) go in the background
or get a long timeout. To wait for a detached run, poll its log for an end marker
(`pgrep -f` also matches the waiting shell).

## Subagents

The Lean coverage runs one coverage agent per group of TeX files, then an
independent reviewer agent, then a fix pass by the first agent. The briefs are in
`editorial/lean_coverage/AGENT_BRIEFS.md`. Each agent runs at most one Lean process
(up to about 5 GB, mostly shared memory maps), so choose how many run at once by
the machine's memory. Agents keep scratch files outside the repository, never run
`lake build` and never commit; the coordinating agent checks their work, builds,
commits and pushes.

If the author asks to pause, ask each running agent to write its reading, item
plan and decisions to `editorial/lean_coverage/pause_notes/<group>.md` and stop.
On 14 October this was done with a steering message to each session through the
OpenCode server API (`POST /api/session/<sessionID>/prompt` with body
`{"text": …, "delivery": "steer"}`, basic auth user `opencode` with
`$OPENCODE_SERVER_PASSWORD`).
