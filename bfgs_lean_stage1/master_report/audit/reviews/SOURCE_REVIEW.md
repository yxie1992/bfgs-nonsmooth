# Independent module-owned declaration collector review

Read the full AllDeclarations.lean and UnifiedAllDeclarations.lean, the pinned Lean.Util.CollectAxioms implementation, and verify_all_declarations.py. The Lean driver hashes are frozen in source_hashes.json. No reviewed proof or tool was edited by this reviewer.

The collection is not limited to theorem-name prefixes. It enumerates actual imported-module ownership, includes private/generated declarations and every safe nonpartial definition/type/constructor/recursor as an independent root, and traverses all dependencies through the checked environment. The unified scope adds five exact-byte supplemental source modules; its original-claim peer embeds the separate owner declarations, avoiding duplicate imports.

Every ConstantInfo case agrees with CollectAxioms: theorem/definition/opaque type and value; constructor and recursor type; inductive type plus constructors; axiom and quotient as terminal cases. Complete outgoing dependency arrays are constructed before reverse reachability. A visited worklist handles cycles without prematurely caching incomplete axiom sets. Missing checked constants and any unsafe/partial node reachable from a safe root reject the run. Each resulting axiom set is explicitly checked against propext, Classical.choice and Quot.sound.

The final strengthened drivers compare elaboration and checked type, dependency list, kind, safety, partiality and universe parameters; all displayed type/value/structural edges then use the checked ConstantInfo. This closes the reviewer's earlier suggestion concerning reported-value provenance. The type-is-a-proposition field is correctly documented: a declaration whose type is Prop itself need not have isProp=true; proposition-valued definitions are nevertheless separately audited through both type and body.

The excluded unsafe/compiler entries are not mathematical premises merely because some have ConstantInfo.axiomInfo representation. The independent graph rejects reachability of any such entry from every safe root; the audit also records them rather than hiding them. This distinction and the standard-kernel/library trust boundary are explicit. Imported dependency assertions, exact module-set completeness and proof-source/driver hashes remain needed in the surrounding runner.

One actionable tooling/prose defect was found in the first closed fresh evidence: the 61 previously omitted main theorem roots consist of 59 names beginning _private. and two other generated equation lemmas, isEmptyElim.eq_1 and signHom.eq_1. compare() required all 61 to have the private prefix and therefore marked the run FAIL despite completed Lean commands and matching input hashes. The owner was notified to correct the classification and refresh the evidence. This source review finds no mathematical collector defect, but does not claim the still-rejected closed run passed. The classification belongs in the final review after the correction; no compiler execution was repeated by this reviewer.
