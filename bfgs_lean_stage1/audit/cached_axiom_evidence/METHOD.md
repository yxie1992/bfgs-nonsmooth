# Shared dependency graph axiom audit experiment

This is an audit implementation experiment, not a mathematical premise or a replacement for the current release gate.

The pinned Lean 4.19.0 implementation, copied as `CollectAxioms.lean`, starts a fresh visited set for each declaration. It reads `env.checked.get`, treats an axiom as a terminal reported vertex, ignores quotient primitive vertices, visits the type and body of definitions/theorems/opaque constants, visits only the type of constructors/recursors, and visits the type plus every constructor of an inductive declaration. `CachedAxiomGraph.directDependencies` reproduces exactly these cases, using Lean's same `Expr.getUsedConstants`. The similarly named `ConstantInfo.getUsedConstantsAsSet` has different cases and is deliberately not substituted.

A first traversal stores every reachable vertex's complete outgoing dependency edges before visiting its children. Encountering an already visited vertex stops expansion but never removes its recorded outgoing edges. Thus inductive/constructor recursion and general cycles remain represented. This phase does not cache intermediate axiom sets.

For each discovered axiom vertex, a visited worklist traverses the reversed graph. A constant is reached exactly when its original forward dependency graph has a finite path to that axiom. This is the same reachability condition as Lean's collector. It is also the least fixed point of axiom-set propagation, so a cycle with no outgoing path to an axiom has the empty set; a cycle with paths to two axioms has both. Every discovered axiom is processed, with no whitelist-based early stopping. The allowed-axiom check is a separate validation after extraction.

`CycleChecks.lean` checks seven graph cases: isolated vertex, self-loop, mutual cycle, cycle connected to an axiom, unreachable cycle, diamond/cycle, and multiple-axiom propagation with an unrelated axiom and cycle. These executable checks supplement the algorithm review; they do not constitute a theorem about the implementation.

The scratch driver reads actual environment theorem declarations and actual types. It reports all current project theorems and adds every one of the 152 scoped declarations, including definitions and generated fields. Its exhaustive comparison checks every old 7,486 theorem's printed actual type and axiom set, and every new scoped declaration's axiom set. It does not infer equality from representative samples. The baseline is a frozen copy of the completed release16 inventory and the successful ordinary scoped collector output.

Initial measured command work was 16.049 seconds: 5.851 seconds to extract the graph, 3.705 seconds for reverse reachability, and 6.493 seconds to print all actual types. The graph had 61,417 vertices and 2,678,188 edges; every reachable constant existed in the checked environment. There were exactly three discovered axiom vertices. These timings exclude importing the already compiled modules and are not a promised whole-gate wall-clock time.

`verify.sh` builds the scratch helper, runs all graph cases, extracts the current audit, and validates every comparison. It uses the existing compiled main library; it does not rebuild or alter the running central gate. `validate.py --new-central audit/declarations.json` additionally compares every actual current theorem type and axiom set after the standard release17 gate has closed. Until that check runs, no claim is made that the full new central inventory has been independently matched.

`prepare_proposed_audit.py` generates only scratch `ProposedAudit.lean`. The proposed inline helper changes the first enumeration loop, preserves the original `BFGS_AUDIT` and `BFGS_AUDIT_COUNT` schema and actual signature computation, fails on any missing checked constant or differing checked/elaboration type, and keeps every later print/example/target command byte-identical. Main `Audit.lean`, project proofs, the lake configuration, toolchain, and checker remain unchanged. Root review and exhaustive final central comparison are required before any future adoption.

Command-count clarification: the preserved remainder has 200 actual `#print axioms` commands. The earlier raw substring count201 included one occurrence inside the old introductory comment; the final validator counts actual command lines and their 200 outputs.
