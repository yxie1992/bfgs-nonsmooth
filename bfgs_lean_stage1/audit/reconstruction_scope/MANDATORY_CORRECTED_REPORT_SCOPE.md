# Mandatory scope of the corrected report companion

The canonical companion must be read together with the preserved report. It is
an explicit author-approved correction layer, not a claim that every immutable
original sentence was true. It should identify the user's clarification that
the original reports were AI-generated and source inputs are unavailable, retain the
original source hashes, and specify precisely which statements are corrected,
reconstructed or replaced. All unchanged mathematical claims retain their full
original hypotheses and conclusions; all explicit open questions remain open
questions. The corrected scope must cover all 14 modules and every original
source span, not merely the newly reconstructed R/E paragraphs.

## Exact completion and validation semantics

The proposed separate fields are:

- `original_snapshot_all_assertions_verified=false` for this reconstructed
  release, because the preserved originals include unsupported historical
  assertions that the new execution does not verify. No assertion that those
  jobs never ran is needed.
- `corrected_report_mathematics_verified`, true only after every retained
  mathematical source span, all nine correction entries and the new explicit R
  construction are mapped to the completed kernel/axiom/strict-contract gate.
- `reconstructed_execution_evidence_verified`, true only after all 19 newly
  specified jobs have actually exited successfully and their logs, counts,
  commands, environment and hashes have been validated.
- `corrected_source_reconciliation_verified`, true only after the full
  original-to-corrected span map, explicit substitutions and preserved-source
  hashes pass independently.
- `corrected_report_verified`, the conjunction of the preceding three
  corrected-scope flags, with a required `verification_scope` field naming the
  canonical companion and its version/hash.

Keep `entire_report_verified=false` if that legacy field continues to denote
the unamended original report. If the schema migrates it, explicitly document
the migration and retain the old meaning under the original-snapshot field;
never silently switch it to corrected-scope semantics.

The closing validator should check the exact set of nine inherited correction
IDs; exact new R/theorem and E19 manifest identities; all14 modules and every
source span; every advertised theorem's actual declaration/type/axiom evidence;
all original bytes; all actual job statuses and log/hash bindings; and the
three explicit numerical/auxiliary substitutions. It should reject a missing
mathematical family even if the job label still exists. The old empirical
counts are not new obligations to manufacture, but their replacement must be
explicit. Completion is of a corrected authored report with actual evidence,
not retrospective verification of unsupported history.
