# Audit evidence history

Current evidence is `STATUS.json`, `build.log`, `axioms.log`, `declarations.json`,
`lean_version.log`, and `mathlib_revision.log`, generated by `scripts/check.py`.
Source hashes tie that status to the checked files.

- `environment_attempt.log`, `preflight.log`, and `static_scan.log` accompanied
  the original uncompiled draft. They are historical, not compiler evidence.
- `bootstrap_initial.log` records the first requested bootstrap in this session:
  no Lean/Lake executable was initially available.
- `elan_install.log` records local installation. `bootstrap.log` records initial
  dependency setup and the native macOS cache-loader failure.
- `cache_interpreted.log` records the successful pinned interpreted-cache fallback.
- `build_initial.log` records the first successful build of the original drafts.
- Named module build/axiom logs record intermediate compiled milestones.
- `history/integration_during_edit.log` and its status capture a transient failed
  integration check during tactic cleanup; the final clean run supersedes it.
- `history/initial_manifest.json` preserves the original draft package manifest.
- `STATEMENT_REVIEW.md` records independent agent review of mathematical scope.
- `target_preservation.log` records comparison of the original target/definition
  code with the initial pushed checkpoint.
- `bootstrap_final.log` records the final bootstrap from a clean project build
  directory, separate from the historical bootstrap log.

Historical successful logs do not certify later source changes. Current status
and its full compiler/axiom transcripts certify the delivered source state.
Binary toolchain, cache, and build artifacts stay in ignored project directories;
version pins and source/audit artifacts are tracked by Git.
